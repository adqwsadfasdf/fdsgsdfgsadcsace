# Telegraph-менеджер — Telegram-бот для массового создания и аналитики публикаций Telegraph

Личный бот: создаёт пачку публикаций Telegraph по одному шаблону (один заголовок и текст, разные
авторы → отдельная ссылка для каждого), хранит их в SQLite и отслеживает просмотры через
официальный Telegraph API.

## Возможности

| Раздел | Что умеет |
|---|---|
| 📝 Создать | **По образцу:** один раз даёте ссылку на готовый пост Telegraph — бот копирует заголовок и текст со всем оформлением (жирный, ссылки, картинки), а под заголовком ставит имя, которое вы пришлёте (можно несколько, каждое с новой строки). Образец запоминается, его можно сменить. Запасной вариант «✍️ Вручную»: Мастер «заголовок → текст → авторы», предпросмотр, предупреждение о ранее использованных авторах, прогресс «Создание публикаций: 3 из 10», остановка, отчёт со ссылками, продолжение прерванной партии |
| 📥 Добавить готовые | Свои страницы, созданные не через бота: по ссылкам (каждая с новой строки), все страницы аккаунта Telegraph разом, подключение другого аккаунта по токену (чтобы их можно было и редактировать) |
| 🕵️ Конкуренты | Отслеживание просмотров чужих публикаций по ссылкам, группировка по конкурентам, рейтинг конкурентов, сравнение «ваши / конкуренты» в среднем на публикацию, списки с сортировками, Excel. В вашу статистику, рейтинг авторов и уведомления конкуренты не попадают |
| 📚 Все публикации | Пагинация, 11 видов сортировки, карточка с подробной статистикой и периодами 24 ч / 7 дн. / 30 дн. / всё время, режим выбора для массовых операций, партии |
| 📊 Статистика | Итоги проекта, суммарный прирост, количество растущих / стабильных / снижающихся, ручное обновление |
| 🏆 Лучшие публикации | Лидеры за 24 ч, 7 дн., 30 дн., за всё время, самые быстрые, перспективные, 🔥 «набирают популярность», ⚠️ «низкая активность» |
| 👥 Рейтинг авторов | 5 сортировок, карточка автора, полная история публикаций автора |
| 🔍 Поиск | Автор, заголовок, дата/период, ссылка Telegraph, ссылка YouTube, метка, избранное — фильтры комбинируются |
| 🎬 Группы YouTube | Привязка ссылки к одной/многим публикациям, группы по видео со статистикой, смена ссылки (с объединением групп), расформирование |
| ⭐ Избранное | Кнопка в карточке и массово |
| 📥 Экспорт Excel | Все / автор / группа / избранное / поиск / выбранные / партия → .xlsx прямо в чат |
| ⚙️ Настройки | Интервалы сбора, пороги статусов, уведомления, аккаунт Telegraph, резервная копия БД |

Массовые операции над выбранными: привязать/отвязать YouTube, метка, избранное, правка заголовка или
текста в Telegraph (editPage), экспорт, удаление из базы (с подтверждением; **страницы Telegraph не удаляются**).

## Статистика: что реально даёт Telegraph API

Telegraph API (метод `getViews`) возвращает:
* общий счётчик просмотров страницы (без параметров даты);
* просмотры за конкретный **календарный** день / час (`year`, `month`, `day`, `hour`).

«Последние 24 часа / 7 / 30 дней» API **не отдаёт**. Поэтому бот:

1. Каждые N минут (по умолчанию 30, настраивается) сохраняет снимок общего счётчика в SQLite.
2. Прирост за скользящий период = сумма изменений счётчика между снимком на начало периода и последним снимком.
3. Раз в несколько часов загружает фактические просмотры за календарные сутки (последние 30 дней).

В интерфейсе это явно разделено: «факт Telegraph API» (общий счётчик, данные по суткам) и
«расчёт по снимкам» (скользящие периоды). У каждого значения есть пометка точности:

* без пометки — точность не хуже интервала сбора;
* «с момента создания» — публикация моложе периода, отсчёт от нуля;
* `≈` — был перерыв в снимках (бот был выключен), окно расчёта шире периода, указано на сколько;
* `*` / «данные только за …» — история короче периода;
* уменьшение счётчика (корректировка Telegraph) **не вычитается** из прироста и показывается отдельно.

Статусы «📈 Растёт / ➖ Стабильно / 📉 Активность снижается» вычисляются сравнением прироста за 24 ч
с «обычной скоростью» публикации (среднее из прироста за предыдущие сутки и среднесуточного прироста за
остальные дни недели). Публикации младше порога (по умолчанию 48 ч) получают «🆕 Мало данных», а не «спад».
Все пороги настраиваются.

Географии просмотров (страны, города) Telegraph API не предоставляет — бот такие данные не показывает и не выдумывает.

### Без накрутки просмотров

* Бот **никогда не открывает** страницы `telegra.ph` — только запросы к `api.telegra.ph`
  (`getViews`, `getPage`, `getPageList`), которые не засчитываются как просмотры.
* Предпросмотр ссылок во всех сообщениях бота **отключён** — Telegram не загружает страницы для превью.
* Сбор статистики полностью фоновый (APScheduler).

### Готовые и чужие публикации

* При добавлении бот один раз запрашивает `getPage` (без содержимого): заголовок, автор, текущий счётчик.
  Дальше — как для своих: снимки `getViews` по расписанию и данные по дням.
* Прирост считается **с момента добавления** (раньше бот за страницей не следил) — такие периоды помечены
  «данные только за …», пока не накопится история. Фактические просмотры по календарным суткам за последние
  30 дней бот подгружает сразу (`getViews` с датой), так что динамика видна с первого дня.
* Дата создания берётся из адреса страницы (Telegraph добавляет «-ММ-ДД»), год уточняется по `getViews` за годы.
* Своя страница из другого аккаунта Telegraph отслеживается, но редактировать её можно только после
  подключения токена того аккаунта («📥 Добавить готовые → 🔑 Страницы другого аккаунта»). Сообщение с токеном
  бот сразу удаляет из чата.
* Публикации конкурентов редактировать нельзя; удаление касается только записей в боте.

### Защита от дублей при создании

* Партия и список авторов сохраняются в БД до первого запроса; каждый элемент имеет статус.
* Если `createPage` не вернул ответ (тайм-аут/обрыв), бот не повторяет запрос вслепую, а сверяется со
  списком страниц аккаунта (`getPageList`) и создаёт страницу только если её нет.
* Повторное нажатие «Создать» не запускает вторую копию; две партии одновременно не выполняются.
* После аварийного перезапуска бот сам восстанавливает прерванную партию, присылает отчёт
  «что создано / что нет» и кнопку «🔁 Создать оставшиеся».
* Ошибка одной публикации не ломает партию — остальные продолжают создаваться.

## Установка

Рекомендуется **Python 3.12 или новее** (проверено на 3.13; синтаксис совместим с 3.10+).

### 1. Создайте бота в BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Введите имя (например, «Мой Telegraph-менеджер») и username, оканчивающийся на `bot`.
3. Скопируйте выданный токен вида `1234567890:AA...` — это `BOT_TOKEN`.
4. (Необязательно) `/setprivacy` → Enable, `/setjoingroups` → Disable — бот личный.

### 2. Узнайте свой Telegram ID

Напишите [@userinfobot](https://t.me/userinfobot) — он пришлёт число `Id`. Это `ADMIN_ID`.
Все остальные пользователи получат «⛔ Доступ запрещён».

### 3. Токен Telegraph

Вариант А (проще): **оставьте `TELEGRAPH_TOKEN` пустым**. При первом запуске бот сам вызовет
`createAccount`, сохранит токен в базе и будет использовать его. Посмотреть аккаунт и получить
одноразовую ссылку для входа в Telegraph в браузере: «⚙️ Настройки → 🧾 Аккаунт Telegraph».

Вариант Б (свой аккаунт): создайте аккаунт запросом и вставьте `access_token` в `.env`:

```bash
curl "https://api.telegra.ph/createAccount?short_name=MyBot&author_name=MyBot"
```

Ответ: `{"ok":true,"result":{"short_name":"MyBot",...,"access_token":"abc123..."}}` — скопируйте `access_token`.
Храните токен в секрете: он даёт право редактировать все страницы аккаунта.

### 5. Заполните `.env`

Скопируйте пример и отредактируйте:

```bash

```

(на Windows: `copy .env.example .env`)

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен от BotFather |
| `ADMIN_ID` | да | Ваш Telegram ID (можно несколько через запятую) |
| `TELEGRAPH_TOKEN` | нет | Токен Telegraph; пусто — создастся автоматически |
| `TELEGRAPH_SHORT_NAME` | нет | Имя аккаунта при автосоздании |
| `TELEGRAPH_AUTHOR_URL` | нет | Ссылка автора для всех публикаций |
| `DATABASE_PATH` | нет | Путь к SQLite (по умолчанию `data/bot.db`) |
| `BACKUP_DIR`, `LOG_DIR`, `LOG_LEVEL` | нет | Каталоги копий и логов, уровень логирования |
| `TIMEZONE` | нет | Часовой пояс отображения и поиска по дате (`Europe/Moscow`) |
| `SNAPSHOT_INTERVAL_MINUTES` | нет | Начальный интервал снимков (потом меняется в настройках бота) |
| `TELEGRAPH_TIMEOUT`, `TELEGRAPH_MIN_INTERVAL`, `TELEGRAPH_MAX_RETRIES`, `TELEGRAPH_CONCURRENCY` | нет | Тайм-аут, пауза между запросами, повторы, параллельность |

### 6. Запуск

```bash
python bot.py
```

Откройте бота в Telegram и нажмите `/start`. Логи: консоль и `logs/bot.log` (с ротацией).

### Запуск как службы (Linux, systemd)

Создайте `/etc/systemd/system/telegraph-bot.service`:

```ini
[Unit]
Description=Telegraph manager bot
After=network-online.target

[Service]
WorkingDirectory=/opt/telegram_telegraph_bot
ExecStart=/opt/telegram_telegraph_bot/.venv/bin/python bot.py
Restart=always
RestartSec=5
User=botuser

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
```

```bash
sudo systemctl enable --now telegraph-bot
```

```bash
journalctl -u telegraph-bot -f
```

На Windows бота можно запускать через «Планировщик заданий» (действие: `.venv\Scripts\python.exe bot.py`,
рабочая папка — каталог проекта, триггер «При входе в систему», перезапуск при сбое).

### Размещение на bothost.ru

1. Соберите архив: `python make_bothost_zip.py` — появится `telegram_telegraph_bot_bothost.zip`
   (без `.env`, `data/`, `logs/`, `backups/`, `.venv`, тестов; `bot.py` и `requirements.txt` — в корне архива).
2. В панели bothost: создайте бота → загрузка из архива → выберите этот zip.
3. «Дополнительные настройки» → **Главный файл (точка входа)**: `bot.py`.
4. «Переменные окружения» (файл `.env` на bothost не нужен):

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather (bothost подставляет сам — проверьте, что он есть) |
| `ADMIN_ID` | ваш Telegram ID (обязательно) |
| `DATABASE_PATH` | `/app/data/bot.db` |
| `BACKUP_DIR` | `/app/data/backups` |
| `LOG_DIR` | `/app/data/logs` |
| `TIMEZONE` | `Europe/Moscow` |

На bothost между перезапусками сохраняется только папка `/app/data`, поэтому база, копии и логи — там.
**Берите платный тариф**: по описанию bothost на бесплатном возможен «спящий режим» (пропуски в статистике)
и стирание данных при перезапуске. Проверка после запуска: создайте или добавьте одну публикацию,
перезапустите бота в панели и убедитесь, что она осталась в «📚 Все публикации».
Обновление: соберите новый архив и нажмите «Обновить из архива» — база в `/app/data` сохраняется,
структура обновляется автоматически.

## Резервное копирование SQLite

База — один файл `data/bot.db` (режим WAL). Копировать его «на лету» простым копированием нельзя —
используйте один из безопасных способов:

* **Из бота:** «⚙️ Настройки → 💾 Резервная копия» — копия создаётся в `backups/` и присылается в чат.
* **Из командной строки** (можно во время работы бота):

```bash
python backup.py
```

* **По расписанию (cron, ежедневно в 4:00):**

```bash
0 4 * * * cd /opt/telegram_telegraph_bot && .venv/bin/python backup.py >> logs/backup.log 2>&1
```

Хранится 30 последних копий. **Восстановление:** остановите бота, замените `data/bot.db` файлом из
`backups/` (удалите рядом лежащие `bot.db-wal` и `bot.db-shm`, если они есть), запустите бота.

## Обновление проекта

1. Сделайте резервную копию: `python backup.py`.
2. Остановите бота (`Ctrl+C` или `sudo systemctl stop telegraph-bot`).
3. Замените файлы проекта новыми (или `git pull`), **не трогая** `.env`, `data/`, `backups/`, `logs/`.
4. Обновите зависимости:

```bash
pip install -r requirements.txt --upgrade
```

5. Запустите бота. Таблицы создаются автоматически, недостающие колонки старой базы добавляются без потери
   данных; если база создана более новой версией, бот откажется запускаться с понятным сообщением,
   а не повредит данные.

## Тесты

Тесты используют локальный mock Telegraph API и фейковую сессию Telegram — реальные страницы не создаются.

```bash
pip install -r requirements-dev.txt
```

```bash
python -m pytest -q
```

Покрыто: создание партии, отсутствие дублей при тайм-ауте `createPage`, FLOOD_WAIT, частичный сбой и
продолжение, восстановление после падения, расчёт прироста и качества данных, сброс счётчика, статусы,
сбор снимков и данных по дням, YouTube-группы и их объединение, поиск с комбинированием фильтров,
избранное, массовые операции, правка через editPage, экспорт Excel, уведомления без повторов,
переназначение интервала планировщика, ограничение доступа и полный сценарий через обработчики бота
(с проверкой HTML-разметки и длины callback_data).

### Таблицы БД

* `publications` — заголовок, автор, текст (HTML и JSON-узлы), ссылка, path, дата, текущие просмотры,
  YouTube-группа, избранное, метка, статус активности, аккаунт Telegraph, последняя ошибка,
  тип (`created` — создана ботом, `imported` — своя готовая, `competitor` — чужая), конкурент, дата начала отслеживания.
* `competitors` — конкуренты (группы чужих публикаций).
* `view_snapshots` — история счётчика (время, значение, изменение) — основа расчёта прироста.
* `daily_views` — фактические просмотры за календарные сутки из API.
* `authors` — все когда-либо использованные авторы (сохраняются и после удаления публикаций).
* `youtube_videos` — группы по видео; `batches` / `batch_items` — партии создания и статусы элементов.
* `selected_publications`, `notification_log`, `settings`, `app_state`, `telegraph_accounts`.

Состояние мастеров (FSM) тоже хранится в SQLite — незавершённый ввод переживает перезапуск.

## Частые вопросы

**Почему у новой публикации «Мало данных»?** Статус «спад» нельзя честно присвоить без истории — нужен
минимальный возраст (настраивается) и снимки за двое суток.

**Почему прирост с «≈»?** Бот не работал часть времени, ближайший снимок до начала периода старше —
окно расчёта получилось шире, это указано в карточке.

**Данные по суткам и прирост за 24 ч различаются?** Это разные величины: календарные сутки (границы задаёт
Telegraph) и скользящие 24 часа до текущего момента.

**Удалил запись — страница пропала?** Нет. Удаление касается только базы бота, страница Telegraph остаётся.

**Отслеживание влияет на счётчик конкурента?** Нет. Бот не открывает страницы, а `getViews` — публичный
метод API, который только читает счётчик и не добавляет просмотров.
